# idletest

Test idle request timeouts in Kubernetes.

This is a small FastAPI application that waits for a requested number of
seconds before returning a JSON response.

## Endpoint

```text
GET /idle={seconds}
```

`seconds` must be an integer from `0` through `600`.

Examples:

```bash
curl http://localhost:8080/idle=0
curl http://localhost:8080/idle=5
```

Successful response:

```json
{"message":"Waited for 5 seconds"}
```

Invalid values return `400`:

```bash
curl -i http://localhost:8080/idle=-1
curl -i http://localhost:8080/idle=601
```

## Gateway Configuration

The app supports two deployment modes:

- Standalone mode: the app is reached directly as `HOST/idle={seconds}`. This
  is the default, and no gateway environment variables are required.
- Gateway route mode: the app is exposed behind an ingress gateway under an
  external host and path prefix. Enable this mode with
  `INGRESS_GATEWAY_ENABLED=true`.

When gateway route mode is enabled, set `INGRESS_GATEWAY_HOST` to the external
gateway host. If the gateway exposes the app under a path prefix and strips that
prefix before proxying to the pod, set `INGRESS_GATEWAY_PATH` to that external
prefix.

| Variable | Required | Example | Description |
| --- | --- | --- | --- |
| `INGRESS_GATEWAY_ENABLED` | No | `true` | Enables gateway-aware redirect rewriting. Defaults to standalone mode when unset or `false`. Accepted true values are `true`, `1`, `yes`, and `on`. Accepted false values are `false`, `0`, `no`, `off`, and blank. |
| `INGRESS_GATEWAY_HOST` | Only when gateway mode is enabled | `myapp.local` | External gateway host used in redirect `Location` headers. It may include a scheme, such as `https://myapp.local`. |
| `INGRESS_GATEWAY_PATH` | Only when gateway mode is enabled | `/idletest` | External gateway path prefix. Use `/` when the app is exposed at the gateway root. |

When `INGRESS_GATEWAY_ENABLED=true`, missing host or path variables cause
startup errors similar to:

```text
INGRESS_GATEWAY_HOST environment variable must be defined
INGRESS_GATEWAY_PATH environment variable must be defined
```

## Gateway-Aware Redirects

When gateway route mode is enabled, any redirect generated by the app or
framework will use the configured host and path in the `Location` header
instead of the internal pod/service host.

The app still receives requests on its internal route. For example:

| External gateway request | Request forwarded to the app |
| --- | --- |
| `https://myapp.local/idletest/idle=5` | `/idle=5` |

Examples:

```bash
INGRESS_GATEWAY_ENABLED=true INGRESS_GATEWAY_HOST=myapp.local INGRESS_GATEWAY_PATH=/ python -m uvicorn idletest_app:app --host 0.0.0.0 --port 8080
INGRESS_GATEWAY_ENABLED=true INGRESS_GATEWAY_HOST=https://myapp.local INGRESS_GATEWAY_PATH=/ python -m uvicorn idletest_app:app --host 0.0.0.0 --port 8080
INGRESS_GATEWAY_ENABLED=true INGRESS_GATEWAY_HOST=myapp.local INGRESS_GATEWAY_PATH=/idletest python -m uvicorn idletest_app:app --host 0.0.0.0 --port 8080
```

If `INGRESS_GATEWAY_HOST` does not include a scheme, the app preserves the
request scheme, or uses `X-Forwarded-Proto` when the gateway sends it.

For example, when the external URL is `https://myapp.local/idletest/idle=5`
and the gateway forwards the request to the pod as `/idle=5`, redirect
responses from the pod will point back to `https://myapp.local/idletest/...`.

## Run Locally

Install dependencies and start the application on port `8080`:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -m uvicorn idletest_app:app --host 0.0.0.0 --port 8080
```

Then hit the app:

```bash
curl http://localhost:8080/idle=3
```

## Run With a Container

Build and run the image:

```bash
docker build -f Containerfile -t idletest:local .
docker run --rm -p 8080:8080 idletest:local
```

Then hit the app:

```bash
curl http://localhost:8080/idle=3
```

If you use Podman, the same commands work with `podman` instead of `docker`.

## Run in Kubernetes

Apply the deployment and service:

```bash
kubectl apply -f idletest-app.yaml
```

The deployment sets `INGRESS_GATEWAY_ENABLED=true`, `INGRESS_GATEWAY_HOST` to
`gateway.example.com`, and `INGRESS_GATEWAY_PATH` to `/xyz`. Change those
values to match the host and path configured on your ingress gateway.

To hit the service without using ingress, port-forward the service:

```bash
kubectl port-forward svc/idletest 8080:8080
curl http://localhost:8080/idle=3
```

To hit the app through your ingress gateway, make sure `gateway.example.com`
resolves to your gateway address, then run:

```bash
curl http://gateway.example.com/xyz/idle=3
```

Or call the gateway address directly with the host header:

```bash
curl -H "Host: gateway.example.com" http://<GATEWAY_IP>/xyz/idle=3
```

Configure your gateway timeout settings as needed. For example, if the gateway
idle timeout is `10` seconds, `/idle=5` should complete while `/idle=11` is
useful for testing timeout behavior through the gateway.
